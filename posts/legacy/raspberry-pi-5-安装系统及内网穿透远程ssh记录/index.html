安装系统

写入系统

我们希望使用Raspberry Pi OS Lite搭配KDE Plasma桌面，具体参考视频 KDE Plasma on Raspberry Pi OS with GREAT Performance! | Installation Guide。

从官方网站下载Raspberry Pi Imager，插入micro SD卡，选择的操作系统为Raspberry Pi OS Lite，32位与64位均可，为了提高性能可以选择64位。点击NEXT进入下一步，进入编辑设置。

General中配置好Username和WiFi，并在Services中选择开启SSH。

保存之后刷入镜像，等待刷入完成后把SD卡插入树莓派启动。关于两种控制方式：

  • 有显示器
  • 无显示器（SSH）

无显示器

无显示器的情况下，一定需要在刷入镜像之前打开SSH连接。常用的SSH连接工具是Putty。确保树莓派处于配置文件中写入对应SSID和密码的WLAN，然后开始SSH连接。我们直接使用命令行的ssh命令。

ssh username@hostname

使用如下命令进入ssh。其中，username是刚刚写入配置文件的用户名，hostname则是在同一WLAN下的IP地址，如果不确定，可以：

  • 查找路由器背部的登录地址和密钥，登陆后查看连接的机器对应的IP地址；
  • 如果是手机热点，可以尝试查看是否显示连接设备分配的IP地址；
  • 如果上述方法均不奏效，可以通过ipconfig（Windows下）查询本机在WLAN下的IP地址（WLAN连接下的IPv4地址），然后使用批处理cmd文件ping其附近的ip地址来查找可用的，并逐个尝试SSH连接。

如果查找不到设备或者查找不到设备的IP地址，那么只能使用显示器进行操作。

Note

如果显示认证失败，有可能是username没有在之前设置，此时可以尝试Lite OS的默认账户： shell pi # username raspberry # password 如果也不成功，那么把SD卡重新插入PC查看配置文件中的username（密码是无法查看的，因为进行了加密，如果密码也忘了，那么只能重新刷入，或者使用显示器）。

成功之后会显示如图：

有显示器

步骤比没有显示器简单很多，只需要接入显示器，等待系统初始化完成后输入用户名和密码即可进入CLI界面。如果网络未连接成功，可以使用nmcli工具进行连接。

# check network status
nmcli network connectivity
# or
nmcli n c

# detect nearby wifi signals
nmcli dev wifi list

# connect to a wifi with SSID and password
nmcli dev wifi connect "YOUR_SSID" password "your_password"

镜像源配置

Lite OS有两个文件需要配置，一个是 ，另一个是，这两个都需要进行修改以提升包安装的速度。使用nano或者vim进行编辑，注意要使用超级管理员sudo操作。以使用清华源为例，分别按照对应页面操作，把对应内容写入文件：

  • sources.list：(https://mirrors.tuna.tsinghua.edu.cn/help/debian/)
  • raspi.list：(https://mirrors.tuna.tsinghua.edu.cn/help/raspberrypi/)

写入之后可以进行当前软件的更新：

sudo apt update
sudo apt upgrade

安装KDE（可选）

KDE共有三个版本：

  • kde-full
  • kde-standard
  • kde-plasma-desktop
    kde-full是kde的完整版本，拥有大量的桌面功能，但是不建议在树莓派上使用，这可能会造成较大负担；plasma是轻量版本，有更少的预安装程序。可以自由选择后两者在树莓派上安装，只需要输入
sudo apt install kde-standard
# or
sudo apt install kde-plasma-desktop

安装过程会比较慢，耐心等待完成安装即可。

然后确认sddm是否开启，然后进入KDE桌面：

systemctl status sddm
# if not enabled
sudo systemctl enable sddm

sudo systemctl start sddm

进入桌面。可以把动画效果关到最小来实现最好的性能。

配置远程SSH

这里以sakurafrp为例，部分参考：

  • 客户端下载

首先使用脚本

sudo bash -c ". <(curl -sSL https://doc.natfrp.com/launcher.sh)"

安装客户端。安装完成会自动开启服务。然后进入另一个用户目录 /home/natfrp，打开webUI：

./natfrp-service webui --init

开启后会弹出一段安装链接，在sakurafrp网页端保持登录的情况下，在浏览器打开该链接。

注意，如果此时是SSH连接状态，即不在树莓派的浏览器操作时，会显示连接中止的异常，这是因为默认的websocket连接使用的是localhost，而不在树莓派的主机操作则查找不到对应的ws连接，所以我们直接使用网页端的远程管理进行连接，选择对应的主机名称，并使用刚才运行的脚本中填入的连接密码登录。

然后到 服务-隧道列表 创建新的隧道，注意使用TCP隧道和端口22即可。然后回到远程连接管理界面，打开刚刚创建的隧道，并回去查看端口号和节点域名。

使用SSH登录：

ssh -p <port> username@hostname

填入节点域名， 填入对应端口号，同样进行验证，即可完成登录：

Android或者iOS手机和平板可以使用Termius等终端连接工具来进行远程登录，只需要选择对应的地址和端口号即可。

首先，如果使用有线网络进行ssh连接的，一定要先确认 eth0 端口的 metric 值是否比 wlan0 高。使用命令来查看网关信息：

ip route show default

如果 eth0 的 metric 更低，则说明优先级更高，默认的流量就会从有线网络走，这显然是行不通的，具体表现为所有的域名和 ip 地址都无法解析。如果使用的是 dhcpcd 进行地址分配，那么打开 etc/dhcpcd.conf 进行修改。

sudo nano etc/dhcpcd.conf

先连接到校园网，使用 nmcli：

nmcli device wlan connect "scut-student"

现在测试访问

curl -v "1.1.1.1"

如果有 200 OK 的返回头，那么说明成功连接上网络，现在只需要进行认证。

写一个简单的脚本用于登录：

#!/bin/bash

# 配置登录参数
USER_ACCOUNT="" # 账号
USER_PASSWORD="" # 密码
WLAN_USER_IP=$(ip -4 addr show wlan0 | grep -oP '(?<=inet\s)\d+(\.\d+){3}' | head -n 1) # 用户IP
WLAN_AC_IP="192.168.66.187" # 认证服务器IP

# 目标URL
LOGIN_URL="https://202.38.210.131:802/eportal/portal/login"

# 构造请求参数
PARAMS=(
  "callback=dr1003"
  "login_method=1"
  "user_account=${USER_ACCOUNT}"
  "user_password=${USER_PASSWORD}"
  "wlan_user_ip=${WLAN_USER_IP}"
  "wlan_user_ipv6="
  "wlan_user_mac=000000000000"
  "wlan_ac_ip=${WLAN_AC_IP}"
  "wlan_ac_name="
  "jsVersion=4.1.3"
  "terminal_type=1"
)

# 拼接参数
QUERY_STRING=$(IFS="&"; echo "${PARAMS[*]}")

# 发送登录请求
RESPONSE=$(curl -s -k -X POST \
  "${LOGIN_URL}?${QUERY_STRING}" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --connect-timeout 10
)

# 检查登录结果
if [[ "$RESPONSE" == *"成功"* ]]; then
  echo "✅ 登录成功！"
elif [[ "$RESPONSE" == *"在线"* ]]; then
  echo "❌ 用户已经登录！"
  exit 2
else
  echo "❌ 登录失败，返回信息: $RESPONSE"
  exit 1
fi
