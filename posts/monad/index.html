Whiskering

F,G:C→DF, G: \mathcal C \to \mathcal DF,G:C→D 是函子，α:F⇒G\alpha: F \Rightarrow Gα:F⇒G 是自然变换，H:D→EH: \mathcal D \to \mathcal EH:D→E 和 I:E→CI: \mathcal E \to \mathcal CI:E→C 也是函子。

类型论中的 Monad

可以从 类型论（Type Theory） 的角度理解 monad，具体来说我们下面会在 Martin-Löf type theory（MLTT） 内讨论。

首先我们可以把范畴论中的 monad 在类型论中形式化（为了简洁，我们省略上下文 Γ\GammaΓ，并且在无歧义的情况下我们会混用 f(a,b)f(a, b)f(a,b) 与 f(a)(b)f(a)(b)f(a)(b)）：

  • （Monad-form）形成规则：
A:UT(A):U\frac {A: \mathcal U} {\mathsf T(A): \mathcal U}T(A):UA:U​

等价地，这里说明 T\mathsf TT 是一个 type constructor，即 T:U→U\mathsf T: \mathcal U \to \mathcal UT:U→U。

  • （Monad-intro）引入规则：
a:AreturnA(a):T(A)\frac {a: A} {\mathsf{return}_A(a): \mathsf T(A)}returnA​(a):T(A)a:A​

等价地，这里说明 return\mathsf{return}return 具有类型 return:∏A:UA→T(A)\mathsf{return}: \prod_{A: \mathcal U} A \to \mathsf T(A)return:∏A:U​A→T(A)

  • （Monad-elim）消去规则：
m:T(A)x:A⊢f(x):T(B)bindA,B(m,f):T(B)\frac {m: \mathsf T(A) \qquad x: A \vdash f(x): \mathsf T(B)} {\mathsf{bind}_{A, B}(m, f): \mathsf T(B)}bindA,B​(m,f):T(B)m:T(A)x:A⊢f(x):T(B)​

等价地，这里说明 bind\mathsf{bind}bind 具有类型 bind:∏A,B:UT(A)→(A→T(B))→T(B)\mathsf{bind}: \prod_{A, B: \mathcal U} \mathsf T(A) \to (A \to \mathsf T(B)) \to \mathsf T(B)bind:∏A,B:U​T(A)→(A→T(B))→T(B)

  • 恒等规则：

    • Monad-unit-L：
    a:Ax:A⊢f(x):T(B)bindA,B(returnA(a),f)≡f(a):T(B)\frac {a: A \qquad x: A \vdash f(x): \mathsf T(B)} {\mathsf{bind}_{A, B}(\mathsf{return}_A(a), f) \equiv f(a): \mathsf T(B)}bindA,B​(returnA​(a),f)≡f(a):T(B)a:Ax:A⊢f(x):T(B)​
    • Monad-unit-R：
    m:T(A)bindA,A(m,returnA)≡m:T(A)\frac {m: \mathsf T(A)} {\mathsf{bind}_{A, A}(m, \mathsf{return}_A) \equiv m: \mathsf T(A)}bindA,A​(m,returnA​)≡m:T(A)m:T(A)​
    • Monad-assoc：
    m:T(A)x:A⊢f(x):T(B)y:B⊢g(y):T(C)bindB,C(bindA,B(m,f),g)≡bindA,B(m,λa. bindB,C(f(a),g)):T(C)\frac {m: \mathsf T(A) \qquad x: A \vdash f(x): \mathsf T(B) \qquad y: B \vdash g(y): \mathsf T(C)} {\mathsf{bind}_{B, C}(\mathsf{bind}_{A, B}(m, f), g) \equiv \mathsf{bind}_{A, B}(m, \lambda a.\,\mathsf{bind}_{B, C}(f(a), g)): \mathsf T(C)}bindB,C​(bindA,B​(m,f),g)≡bindA,B​(m,λa.bindB,C​(f(a),g)):T(C)m:T(A)x:A⊢f(x):T(B)y:B⊢g(y):T(C)​

这样定义的三元组 (T,return,bind)(\mathsf T, \mathsf{return}, \mathsf{bind})(T,return,bind) 就称为一个 monad。

不妨先来看一个常见的例子，在函数式语言中的 Maybe\mathsf{Maybe}Maybe type constructor（其他语言中比如 Rust 称为 Option<T>，同理下方的 constructor 就是 None 和 Some(T)）。它通常定义两个 constructor：

nothing:∏A:UMaybe(A),just:∏A:UA→Maybe(A)\mathsf{nothing}: \prod_{A: \mathcal U} \mathsf{Maybe}(A), \qquad \mathsf{just}: \prod_{A: \mathcal U} A \to \mathsf{Maybe}(A)nothing:A:U∏​Maybe(A),just:A:U∏​A→Maybe(A)

那么 return\mathsf{return}return 就是 just\mathsf{just}just。bind\mathsf{bind}bind 怎么定义呢？如果在 Rust 中寻找这么一个签名的函数，那么 Option::and_then 就是一个可能的选择。不妨看看他的实现：

pub const fn and_then<U, F>(self, f: F) -> Option<U>
where
    F: [const] FnOnce(T) -> Option<U> + [const] Destruct,
{
    match self {
        Some(x) => f(x),
        None => None,
    }
}

同样地，Haskell 的 Maybe 实现了 Monad 类的运算符 >>= 即 bind\mathsf{bind}bind：

instance Monad Maybe where
    (Just x) >>= k = k x
    Nothing  >>= _ = Nothing
    return = Just
    ...

那么非常一目了然，按照此定义的 bind\mathsf{bind}bind 就是

bind(just(a),f):≡f(a)bind(nothing,f):≡nothing\begin{align*} \mathsf{bind}(\mathsf{just}(a), f) & :\equiv f(a) \\ \mathsf{bind}(\mathsf{nothing}, f) & :\equiv \mathsf{nothing} \end{align*}bind(just(a),f)bind(nothing,f)​:≡f(a):≡nothing​

不妨来据此验证后三条规则。第一条就是定义，不必多说：

bind(just(a),f)≡f(a)\mathsf{bind}(\mathsf{just}(a), f) \equiv f(a)bind(just(a),f)≡f(a)

第二条和第三条分别可以分类讨论 mmm 可证明：

bind(m,just)≡m\mathsf{bind}(m, \mathsf{just}) \equiv mbind(m,just)≡m bind(bind(m,f),g)≡bind(m,λa. bind(f(a),g))\mathsf{bind}(\mathsf{bind}(m, f), g) \equiv \mathsf{bind}(m, \lambda a.\,\mathsf{bind}(f(a), g))bind(bind(m,f),g)≡bind(m,λa.bind(f(a),g))

我们尝试用 Rust 来表示上面的后两条，其实说的就是：

o.and_then(Some) = o
o.and_then(f).and_then(g) = o.and_then(|a| f(a).and_then(g))

我们可以举出更多常见的例子，比如列表 (List,λx.[x],flatMap)(\mathsf{List}, \lambda x. [x], \mathsf{flatMap})(List,λx.[x],flatMap) 等。

如何理解这三条规则呢？如果把 T(A)\mathsf T(A)T(A) 理解成某种对 AAA 的包装，那么，这三条分别可以理解成：

  • 纯值先包装再绑定，和直接把纯值交给下一步，完全一样
  • 一个计算做完后（即拿到一个 mmm），把结果原样 return 回去，不应该改变这个计算本身
  • 效果顺序是稳定的，组合可以安全地拆分和重构

根据 monad 的抽象，我们可以仅依赖 monad 本身定义一个函数 fmap\mathsf{fmap}fmap：

fmap:∏A,B:U(A→B)→T(A)→T(B)fmapA,B(f,m):≡bindA,B(m,λa. returnB(f(a)))\mathsf{fmap}: \prod_{A, B: \mathcal U} (A \to B) \to \mathsf T(A) \to \mathsf T(B) \\ \mathsf{fmap}_{A, B}(f, m) :\equiv \mathsf{bind}_{A, B}(m, \lambda a.\,\mathsf{return}_B(f(a)))fmap:A,B:U∏​(A→B)→T(A)→T(B)fmapA,B​(f,m):≡bindA,B​(m,λa.returnB​(f(a)))

实际上在 Haskell 中 Monad 类继承自 Functor 类，在 Functor 类上就有一个方法叫作 fmap，你可以用 Monad 类上的 liftM 来作为其默认实现；而 liftM 的实现方式正是上面的方式，利用 >>= 和 return。

而 Rust 可以通过手动按照上面定义组合出，只不过由于 Option / Maybe 的特殊性，fmap 有更简单的定义方式（Rust 中的 Option::map，Haskell 中的 fmap 都是直接模式匹配而非组合函数）：

fn fmap<A, B>(f: impl Fn(A) -> B) -> impl Fn(Option<A>) -> Option<B> {
    move |o| o.and_then(|a| Some(f(a)))
}

let f: Fn(A) -> B = ...;
let o: Option<A> = ...;
assert_eq!(fmap(f, o), o.map(f));

其实可以发现，fmap\mathsf{fmap}fmap 和 bind\mathsf{bind}bind 的类型其实很像，除了参数顺序外，唯一的不同只有传入的函数的返回类型一个是 BBB，一个是 T(B)\mathsf T(B)T(B)。

那么一个自然的问题是，能否反过来从 fmap\mathsf{fmap}fmap 构造出 bind\mathsf{bind}bind 呢？并不可以。因为 bind\mathsf{bind}bind 拿到的函数是 f:A→T(B)f: A \to \mathsf T(B)f:A→T(B)，而 fmap\mathsf{fmap}fmap 接受的是 A→BA \to BA→B。在做完计算 f(...)f(...)f(...) 后拿到的是 T(B)\mathsf T(B)T(B)，但是根据定义并没有一种方式把 T(B)\mathsf T(B)T(B) 类型的值转化成 BBB。在 Maybe\mathsf{Maybe}Maybe 中也很合理，因为一个可能为空的值无法保证它一定拥有值。

类似地可以定义

join:∏A:UT(T(A))→T(A)joinA(m):≡bindT(A),A(m,idT(A))\mathsf{join}: \prod_{A: \mathcal U} \mathsf T(\mathsf T(A)) \to \mathsf T(A) \\ \mathsf{join}_A(m) :\equiv \mathsf{bind}_{\mathsf T(A), A}(m, \mathsf{id}_{\mathsf T(A)})join:A:U∏​T(T(A))→T(A)joinA​(m):≡bindT(A),A​(m,idT(A)​)

在 Rust 的 Option 中可以实现为

let join: impl Fn(Option<Option<A>>) -> Option<A> = |o| o.and_then(convert::identity);


let o: Option<Option<A>> = ...;
assert_eq!(join(o), o.flatten());

其中 Option::flatten 的最初实现就是用的类似上面的实现。而 Haskell 的定义也是类似：

join :: Monad m => m (m a) -> m a
join x = x >>= id

这两个函数有一个非常好的性质。

定理（join-map）

对任意的 m:T(A)m: \mathsf T(A)m:T(A) 和 f:A→T(B)f: A \to \mathsf T(B)f:A→T(B)，有

joinB(fmapA,T(B)(f,m))=bindA,B(m,f)\mathsf{join}_B(\mathsf{fmap}_{A, \mathsf T(B)}(f, m)) = \mathsf{bind}_{A, B}(m, f)joinB​(fmapA,T(B)​(f,m))=bindA,B​(m,f)

为了简洁，我们定义复合

(⋅)∘(⋅):∏A,B,C:U(B→C)→(A→B)→A→C(f∘g,a):≡f(g(a))(\cdot) \circ (\cdot): \prod_{A, B, C: \mathcal U} (B \to C) \to (A \to B) \to A \to C \\ (f \circ g, a) :\equiv f(g(a))(⋅)∘(⋅):A,B,C:U∏​(B→C)→(A→B)→A→C(f∘g,a):≡f(g(a))

证明：

join(fmap(f,m))≡bind(fmap(f,m),id)join 定义≡bind(bind(m,return∘f),id)fmap 定义≡assocbind(m,λa. bind(return(f(a)),id))assoc≡unit-Lbind(m,id∘f)unit-L≡bind(m,f).\begin{aligned} \mathsf{join}(\mathsf{fmap}(f, m)) &\equiv \mathsf{bind}(\mathsf{fmap}(f, m), \mathsf{id}) &&\text{$\mathsf{join}$ 定义}\\ &\equiv \mathsf{bind}(\mathsf{bind}(m, \mathsf{return} \circ f), \mathsf{id}) &&\text{$\mathsf{fmap}$ 定义}\\ &\equiv_{\mathrm{assoc}} \mathsf{bind}(m, \lambda a.\, \mathsf{bind}(\mathsf{return}(f(a)), \mathsf{id})) &&\text{assoc}\\ &\equiv_{\mathrm{unit\text{-}L}} \mathsf{bind}(m, \mathsf{id} \circ f) &&\text{unit-L}\\ &\equiv \mathsf{bind}(m, f). \end{aligned}join(fmap(f,m))​≡bind(fmap(f,m),id)≡bind(bind(m,return∘f),id)≡assoc​bind(m,λa.bind(return(f(a)),id))≡unit-L​bind(m,id∘f)≡bind(m,f).​​join 定义fmap 定义assocunit-L​

这在 Rust 的 Option 中其实就是

let o: Option<A> = ...;
let f: impl Fn(A) -> Option<B> = ...;
assert_eq!(o.map(f).flatten(), o.and_then(f));

Monad 的对应

下面我们来看这样定义的 monad，放在类型范畴 U\mathcal UU 下是否符合范畴论中 monad 的定义。

我们定义 (T,η,μ)(T, \eta, \mu)(T,η,μ)：

函子 TTT：

TA:≡T(A)Tf:≡fmapA,B(f):T(A)→T(B)TA :\equiv \mathsf T(A) \\ Tf :\equiv \mathsf{fmap}_{A, B}(f): \mathsf T(A) \to \mathsf T(B)TA:≡T(A)Tf:≡fmapA,B​(f):T(A)→T(B)

自然变换 η:1U⇒T\eta: 1_{\mathcal U} \Rightarrow Tη:1U​⇒T 和 μ:T2⇒T\mu: T^2 \Rightarrow Tμ:T2⇒T：

ηA:≡returnA:A→T(A)μA:≡joinA:T(T(A))→T(A)\eta_A :\equiv \mathsf{return}_A: A \to \mathsf T(A) \\ \mu_A :\equiv \mathsf{join}_A: \mathsf T(\mathsf T(A)) \to \mathsf T(A)ηA​:≡returnA​:A→T(A)μA​:≡joinA​:T(T(A))→T(A)

下面来验证定义。

函子性

保持单位映射：

令

m:T(A).m: \mathsf T(A).m:T(A).

则

fmap(id,m)≡bind(m,return∘id)≡bind(m,return)≡unit-Rm.\begin{aligned} \mathsf{fmap}(\mathsf{id}, m) &\equiv \mathsf{bind}(m, \mathsf{return} \circ \mathsf{id})\\ &\equiv \mathsf{bind}(m, \mathsf{return})\\ &\equiv_{\mathrm{unit\text{-}R}} m. \end{aligned}fmap(id,m)​≡bind(m,return∘id)≡bind(m,return)≡unit-R​m.​

故

fmap(id)≡id.\boxed{\mathsf{fmap}(\mathsf{id})\equiv \mathsf{id}.}fmap(id)≡id.​

保持复合：

令

m:T(A),g:A→B,f:B→C,m: \mathsf T(A),\qquad g:A\to B,\qquad f:B\to C,m:T(A),g:A→B,f:B→C,

并令

h≡return∘g,k≡return∘f.h \equiv \mathsf{return} \circ g, \qquad k \equiv \mathsf{return} \circ f.h≡return∘g,k≡return∘f.

则

fmap(f,fmap(g,m))≡bind(fmap(g,m),k)fmap 定义≡bind(bind(m,h),k)fmap 定义≡assocbind(m,λa. bind(h(a),k))assoc≡bind(m,λa. bind(return(g(a)),k))h(a)=return(g(a))≡unit-Lbind(m,return∘f∘g)unit-L≡fmap(f∘g,m)fmap 定义.\begin{aligned} \mathsf{fmap}(f, \mathsf{fmap}(g, m)) &\equiv \mathsf{bind}(\mathsf{fmap}(g, m), k) &&\text{$\mathsf{fmap}$ 定义}\\ &\equiv \mathsf{bind}(\mathsf{bind}(m, h), k) &&\text{$\mathsf{fmap}$ 定义}\\ &\equiv_{\mathrm{assoc}} \mathsf{bind}(m, \lambda a.\,\mathsf{bind}(h(a), k)) &&\text{assoc}\\ &\equiv \mathsf{bind}(m, \lambda a.\,\mathsf{bind}(\mathsf{return}(g(a)), k)) && h(a)=\mathsf{return}(g(a))\\ &\equiv_{\mathrm{unit\text{-}L}} \mathsf{bind}(m, \mathsf{return} \circ f \circ g) &&\text{unit-L}\\ &\equiv \mathsf{fmap}(f \circ g, m) &&\text{$\mathsf{fmap}$ 定义}. \end{aligned}fmap(f,fmap(g,m))​≡bind(fmap(g,m),k)≡bind(bind(m,h),k)≡assoc​bind(m,λa.bind(h(a),k))≡bind(m,λa.bind(return(g(a)),k))≡unit-L​bind(m,return∘f∘g)≡fmap(f∘g,m)​​fmap 定义fmap 定义assoch(a)=return(g(a))unit-Lfmap 定义.​

故

fmap(f)∘fmap(g)≡fmap(f∘g).\boxed{ \mathsf{fmap}(f)\circ\mathsf{fmap}(g) \equiv \mathsf{fmap}(f\circ g). }fmap(f)∘fmap(g)≡fmap(f∘g).​

自然性

return\mathsf{return}return 的自然性：

令

a:A,f:A→B.a:A,\qquad f:A\to B.a:A,f:A→B.

则

fmap(f,return(a))≡bind(return(a),return∘f)≡unit-Lreturn(f(a)).\begin{aligned} \mathsf{fmap}(f, \mathsf{return}(a)) &\equiv \mathsf{bind}(\mathsf{return}(a), \mathsf{return} \circ f)\\ &\equiv_{\mathrm{unit\text{-}L}} \mathsf{return}(f(a)). \end{aligned}fmap(f,return(a))​≡bind(return(a),return∘f)≡unit-L​return(f(a)).​

故

return(f(a))≡fmap(f,return(a)).\boxed{ \mathsf{return}(f(a)) \equiv \mathsf{fmap}(f, \mathsf{return}(a)). }return(f(a))≡fmap(f,return(a)).​

join\mathsf{join}join 的自然性：

令

a:T(T(A)),f:A→B.a: \mathsf T(\mathsf T(A)), \qquad f: A \to B.a:T(T(A)),f:A→B.

左边由 join-fmap，取 m=a, k=fmap(f)m=a,\ k=\mathsf{fmap}(f)m=a, k=fmap(f)，得

join(fmap(fmap(f),a))≡bind(a,fmap(f)).\mathsf{join}(\mathsf{fmap}(\mathsf{fmap}(f), a)) \equiv \mathsf{bind}(a, \mathsf{fmap}(f)).join(fmap(fmap(f),a))≡bind(a,fmap(f)).

Combinator 的组合定义

因此我们可以把 combinator 表示出来。首先 bind\mathsf{bind}bind 和 return\mathsf{return}return 直接对应的就是

flatMap:∏A,B:UP(A)→(A→P(B))→P(B)flatMap(p,f):≡bind(p,f)\mathsf{flatMap}: \prod_{A, B: \mathcal U} \mathsf P(A) \to (A \to \mathsf P(B)) \to \mathsf P(B) \\ \mathsf{flatMap}(p, f) :\equiv \mathsf{bind}(p, f)flatMap:A,B:U∏​P(A)→(A→P(B))→P(B)flatMap(p,f):≡bind(p,f)

和

succeed:∏A:UA→P(A)succeed(a):≡return(a)\mathsf{succeed}: \prod_{A: \mathcal U} A \to \mathsf P(A) \\ \mathsf{succeed}(a) :\equiv \mathsf{return}(a)succeed:A:U∏​A→P(A)succeed(a):≡return(a)

以及能从二者定义出来的 fmap\mathsf{fmap}fmap 对应的 combinator

map:∏A,B:UP(A)→(A→B)→P(B)map(p,f):≡fmap(f,p)\mathsf{map}: \prod_{A, B: \mathcal U} \mathsf P(A) \to (A \to B) \to \mathsf P(B) \\ \mathsf{map}(p, f) :\equiv \mathsf{fmap}(f, p)map:A,B:U∏​P(A)→(A→B)→P(B)map(p,f):≡fmap(f,p)

问题与修复

上面的看似都没什么问题，但是下面的定义就开始出现问题了。首先，尝试定义 satisfy\mathsf{satisfy}satisfy：

satisfy:(?→2)→P(?)\mathsf{satisfy}: (? \to \mathbf 2) \to \mathsf P(?) \\satisfy:(?→2)→P(?)

在一般的命令式 Parser 里面，token_stream 是一个列表或者一个迭代器（或者直接把它看成一个持有所有 token 的容器），token_stream.next() 方法通常改变 token_stream 本身并产出一个 token 或者空值。如果把副作用消除，纯化函数，那么更加正确的写法为：

next:Σ→1+I×Σ\mathsf{next}: \Sigma \to \mathbf 1 + I \times \Sigmanext:Σ→1+I×Σ

其中 Σ\SigmaΣ 就是这个容器，III 就是产出的 token 的类型，我们相当于给类型 Σ\SigmaΣ 加上了一条规则约束，要求它具有上面这个函数。所以正确的类型是：

satisfy:(I→2)→P(I)\mathsf{satisfy}: (I \to \mathbf 2) \to \mathsf P(I) \\satisfy:(I→2)→P(I)

利用 sum 的消去子

recA+B:∏C:U(A→C)→(B→C)→A+B→C\mathsf{rec}_{A + B}: \prod_{C: \mathcal U} (A \to C) \to (B \to C) \to A + B \to CrecA+B​:C:U∏​(A→C)→(B→C)→A+B→C

（当然这里也可以直接理解为 Maybe\mathsf{Maybe}Maybe）和 2\mathbf 22（其实就是 Boolean）的消去子

rec2:∏C:UC→C→2→C\mathsf{rec}_\mathbf 2: \prod_{C: \mathcal U} C \to C \to \mathbf 2 \to Crec2​:C:U∏​C→C→2→C

可以定义

satisfy(p,s):≡rec1+I×Σ(what1,λ(x,s′). rec2(returnM(x,s′),what2,p(x)),next(s))\begin{align*} \mathsf{satisfy}(p, s) :\equiv \mathsf{rec}_{\mathbf 1 + I \times \Sigma}( & \mathsf{what}_1, \\ & \lambda (x, s'). \,\mathsf{rec}_\mathbf 2(\mathsf{return}^\mathsf{M}(x, s'), \mathsf{what}_2, p(x)), \\ & \mathsf{next}(s)) \end{align*}satisfy(p,s):≡rec1+I×Σ​(​what1​,λ(x,s′).rec2​(returnM(x,s′),what2​,p(x)),next(s))​

但是有两个地方我们无从得知如何填写。因为从这里开始我们就会报告出两个错误，前一个 what\mathsf{what}what 的错误就是 EOF，后一个 what\mathsf{what}what 的错误就是 predicator 断言为假，由于 M\mathsf MM 是抽象的，我们无法构造任何值。

另一个有问题的例子是：

or:∏A:UP(A)→P(A)→P(A)\mathsf{or}: \prod_{A: \mathcal U} \mathsf P(A) \to \mathsf P(A) \to \mathsf P(A)or:A:U∏​P(A)→P(A)→P(A)

在这里，我们想表达的意思是，如果第一个 parser 解析出问题，那么我们回退到第二个 parser；如果第二个 parser 也出问题，那么应该报错。

这里描述的行为中，我们缺少两个东西来实现：

  • 如何知道出问题？
  • 如何报告一个问题？

其中后面一个问题就与前面 satisfy\mathsf{satisfy}satisfy 遇到的问题一样。我们可以把 M\mathsf MM 具体化。比如一个朴素的想法是取 M=Maybe\mathsf{M} = \mathsf{Maybe}M=Maybe，那么可以定义（标记为 pink{\color{pink} \rm{pink}}pink 的符号表示在作用域内未使用）

what1(x):≡nothingwhat2:≡nothing\begin{align*} \mathsf{what_1}({\color{pink} x}) & :\equiv \mathsf{nothing} \\ \mathsf{what_2} & :\equiv \mathsf{nothing} \\ \end{align*}what1​(x)what2​​:≡nothing:≡nothing​

然后 or\mathsf{or}or 也可以定义为

or(p1,p2)(s):≡recMaybe(recMaybe(nothing,id,p2(s)),id,p1(s))\mathsf{or}(p_1, p_2)(s) :\equiv \mathsf{rec}_\mathsf{Maybe}(\mathsf{rec}_\mathsf{Maybe}(\mathsf{nothing}, \mathsf{id}, p_2(s)), \mathsf{id}, p_1(s))or(p1​,p2​)(s):≡recMaybe​(recMaybe​(nothing,id,p2​(s)),id,p1​(s))

但是这就带来一个问题，如果 parse 有错误，那么我们只能知道发生了错误，却不知道发生了什么错误。这显然是不可接受的。我们可以用另外一个 monad Either(Error)\mathsf{Either}(\mathsf{Error})Either(Error)，其中 Error\mathsf{Error}Error 是给定的错误类型。不管怎么定义 Error\mathsf{Error}Error，比如用 sum type，或者是用 inductive definition

Error:UexpectError,eofError:ErrororError:Error→Error→Error\mathsf{Error}: \mathcal U \\ \mathsf{expectError}, \mathsf{eofError}: \mathsf{Error} \\ \mathsf{orError}: \mathsf{Error} \to \mathsf{Error} \to \mathsf{Error}Error:UexpectError,eofError:ErrororError:Error→Error→Error

都能够区分开来。不过需要注意的一点就是 or\mathsf{or}or 的定义需要修改：

or(p1,p2,s):≡recEither(λe1. recEither(orError(e1),id,p2(s)),id,p1(s))\mathsf{or}(p_1, p_2, s) :\equiv \mathsf{rec}_\mathsf{Either}(\lambda e_1. \,\mathsf{rec}_\mathsf{Either}(\mathsf{orError}(e_1), \mathsf{id}, p_2(s)), \mathsf{id}, p_1(s))or(p1​,p2​,s):≡recEither​(λe1​.recEither​(orError(e1​),id,p2​(s)),id,p1​(s))

这个 orError\mathsf{orError}orError 构造子的作用就是针对 or\mathsf{or}or 的解析错误，能够同时保留二者。至于 Error\mathsf{Error}Error 的具体报错信息，用于展示给用户，实际上也可以做，只需要让构造子接受想要保留的信息作为参数即可，在这里为了简单就只区分错误类型而不保留其他信息。

many\mathsf{many}many combinator 也是一个有问题的地方：

many:∏A:UP(A)→P(List(A))\mathsf{many}: \prod_{A: \mathcal U} \mathsf P(A) \to \mathsf P(\mathsf{List}(A))many:A:U∏​P(A)→P(List(A))

一种可能容易想到的构造方式是

many(p):≡flatMap(p,λx. map(many(p),cons(x)))\mathsf{many}(p) :\equiv \mathsf{flatMap}(p, \lambda x. \,\mathsf{map}(\mathsf{many}(p), \mathsf{cons}(x)))many(p):≡flatMap(p,λx.map(many(p),cons(x)))

但是想到很多函数式语言都不支持递归定义，那么一个可能的解决方案就是使用不动点

fix:∏A:U(A→A)→A\mathsf{fix}: \prod_{A: \mathcal U} (A \to A) \to Afix:A:U∏​(A→A)→A

这也是大部分函数式语言我们可以用的方法：

many(p):≡fix(λm. flatMap(p,λx. map(m,cons(x))))\mathsf{many}(p) :\equiv \mathsf{fix}(\lambda m. \,\mathsf{flatMap}(p, \lambda x. \,\mathsf{map}(m, \mathsf{cons}(x))))many(p):≡fix(λm.flatMap(p,λx.map(m,cons(x))))

但遗憾的是，在大部分类型论中 fix\mathsf{fix}fix 无法被构造，如果强行引入将会破坏可终止性。

那问题出现在哪？实际上上面的分析已经说明了问题，many\mathsf{many}many 实际上可能不能终止。按照上面的定义

many(succeed(⋆))\mathsf{many}(\mathsf{succeed}(\star))many(succeed(⋆))

将无法终止。这说明我们需要一种错误来指示在 many\mathsf{many}many 的一次 parse 中没有前进，并且解析成功的情况，以及判断这种情况的方法。

一种方法是，把 next\mathsf{next}next 改造成

next:Σ→1+I×Σ×N\mathsf{next}: \Sigma \to \mathbf 1 + I \times \Sigma \times \mathbb Nnext:Σ→1+I×Σ×N

其中用 N\mathbb NN 来表示当前 token 的 position，并且 next\mathsf{next}next 前后产生的 position 必须不同，更好的性质则是按照顺序产生。然后引入一种错误构造子

unterminateError:Error\mathsf{unterminateError}: \mathsf{Error}unterminateError:Error

但是这样的问题在于，这个对 next\mathsf{next}next 的约束本身过于复杂，并且它仍然无法让我们产生 inductive definition，虽然在行为上是可以做到正确的。所以我们的方案是，直接让 Σ=List(I)\Sigma = \mathsf{List}(I)Σ=List(I)，这不但避免了 recursive definition，还正确建模了 token stream，因为在之前的 next\mathsf{next}next 的描述下，token stream 是可以无限的。

那么：

next:List(I)→1+I×List(I)\mathsf{next}: \mathsf{List}(I) \to \mathbf 1 + I \times \mathsf{List}(I)next:List(I)→1+I×List(I)

并且之前的 parser monad 的建模：

P(O):≡List(I)→M(O×List(I))≡List(I)→Either(Error,O×List(I))\mathsf P(O) :\equiv \mathsf{List}(I) \to \mathsf M(O \times \mathsf{List}(I)) \equiv \mathsf{List}(I) \to \mathsf{Either}(\mathsf{Error}, O \times \mathsf{List}(I))P(O):≡List(I)→M(O×List(I))≡List(I)→Either(Error,O×List(I))

我们可以归纳定义而非递归定义 many\mathsf{many}many。

many(p,s):≡recN(λs. right((nil,s)),step,length(s),s)\mathsf{many}(p, s) :\equiv \mathsf{rec}_\mathbb N(\lambda s. \,\mathsf{right}((\mathsf{nil}, s)), {\color{blue}\mathsf{step}}, \mathsf{length}(s), s)many(p,s):≡recN​(λs.right((nil,s)),step,length(s),s)

step{\color{blue}\mathsf{step}}step 的定义留作读者练习。

  • cons\mathsf{cons}cons 的定义为

    cons:∏A:UA→List(A)→List(A)\mathsf{cons}: \prod_{A: \mathcal U} A \to \mathsf{List}(A) \to \mathsf{List}(A)cons:A:U∏​A→List(A)→List(A)

Kleisli 范畴

Kleisli Category, Kleisli Arrow

在具有 Monad T=(T,η,μ)\mathbb T = (T, \eta, \mu)T=(T,η,μ) 的范畴 C\mathcal CC 上，定义新的范畴 KT\mathcal K_\mathbb TKT​（无歧义下也记为 KT\mathcal K_TKT​），称为 monad T\mathbb TT 在范畴 C\mathcal CC 上的 Kleisli 范畴。

它的对象是全体 C\mathcal CC 的对象；对于任意两个对象 x,y∈Cx, y \in \mathcal Cx,y∈C，它们之间的态射是 C\mathcal CC 中所有 x→Tyx \to Tyx→Ty 的态射，即 hom⁡KT(x,y)=hom⁡C(x,Ty)\hom_{\mathcal K_T}(x, y) = \hom_\mathcal C(x, Ty)homKT​​(x,y)=homC​(x,Ty)，其态射也被称为 Kleisli 箭头。
